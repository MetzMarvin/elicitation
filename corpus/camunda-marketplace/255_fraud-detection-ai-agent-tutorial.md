## What the page shows

The Fraud Detection AI Agent Tutorial (Camunda, open source, 8.7, quick start). An insurance-fraud process built as an ad-hoc AI agent sub-process: OpenAI-bound tasks assess the fraud risk, run a final check on the result and draft the email inquiry, a human advisor can be called in, SendGrid sends the customer email, and gateways decide whether fraud was detected - with the agent's own failure modelled as an escalation ('FraudDetected') caught on the agent container's boundary.

## Observations (description only, no interpretation)

- **AI activity - function:** assess the fraud risk of the case, run a final check on that result, and generate the email inquiry text - three OpenAI-bound calls inside the agent container.
- **AI activity - element type:** an adHocSubProcess (the BPMN ad-hoc sub-process symbol the page names) containing serviceTasks bound to the OpenAI connector template (io.camunda:http-json:1 underneath) plus a SendGrid-bound 'Send Email'.
- **AI activity - models named:** the OpenAI *connector* is named by the template id; the model itself is not visible in the published fields.
- **Authority - downstream:** the 'Is Fraud Detected?' gateway throws the 'FraudDetected' escalation (and 'Fraud! Detected' sets fraudDetected:=true); the scriptTask 'Decide Tasks to do' shapes which agent tasks run, and the escalation caught on the container boundary ends the process at 'Fraud is detected'.
- **Authority - control (human):** the userTask 'Call on External Advisor' inside the agent container - the page's 'humans in the loop ... knowledge workers have oversight'; the ad-hoc symbol means the agent's tasks are not a fixed sequence.
- **Data reachable by the model:** the tax/claim details captured by the start form (zeebe:formDefinition enter-details-of-tax-1ph5wul, example output fullName/nationalID/dob); the customer email is generated by an AI task before SendGrid sends it.
- **Human role:** the external advisor task, plus the oversight the page claims for the design.
